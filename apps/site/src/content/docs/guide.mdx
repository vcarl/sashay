This page builds one small React app: a chart of houseplants with three panes, Chart, Nearby and Plant. Each section adds one feature, shows the lines that changed, and runs the app as it stands. The full source is on the [Demos](../demos/) page.

## Install

sashay is one ESM package. You use it through React components; underneath is a core with no runtime dependencies, which you can also [use without React](#without-react).

```sh
pnpm add @vcarl/sashay react react-dom
```

React is a peer dependency and needs version 19 or later. Import the components and the stylesheet once. The styles live in `@layer sashay`, so your own CSS wins without a fight.

```tsx
import { Pane, Sashay } from "@vcarl/sashay/react";
import "@vcarl/sashay/style.css";
```

## Your first frame

A frame is a `<Sashay>` with a height. Put one `<Pane>` inside it per pane, in order. sashay creates the edges, grips and close buttons itself.

Each pane says how it opens. `focus` is the fraction of the frame a pane opens to; `title` labels its edge, its compact tab and its close button. `defaultLayout` places the dividers: `[1, 1]` pushes both to the right edge, so only Chart is open.

Your app opens panes with `reveal(id)` and closes them with `close(id)`, on the handle that `ref` gives you. Click a plant and Nearby slides in, listing the plants closest to it. Click the plant again in the list and its card opens in the third pane, at equal thirds because Plant sets `opensTo`. The leaf × closes the rightmost open pane; closing Nearby calls its `onClose`, which clears the pick.

## Keep a point in view

A pane that another pane slides over isn't squished. It keeps its `focus` width and the next pane covers part of it. Give the pane `keepInView` and sashay slides its content left, as little as it can, so that point stays inside the slice that's still showing. The same goes for content wider than the pane, on a phone too. Pass `null` to let go.

`keepInView` is a `Length` measured from the pane's left edge: a number is pixels, and `"40%"` is 40% of the pane's width. The chart here is a fixed 720 pixels wide, so the app passes the picked plant's x in pixels. sashay measures the content's width on resize, so it never slides past the chart's right edge.

This frame opens squeezed, with the Lemon tree picked far over on the right. Drag Nearby's edge back and forth, or pick other plants in the list, and the dot stays in view. The part of the chart that still shows takes clicks as usual.

## Layout in the URL

`onLayoutChange` hands you a code: one hex digit per visible divider, plus the spine offset and which bars are open. It fires on release, click, keypress or a pane-list change, never during a drag. Pass a saved code back as `layout`; invalid input falls back to `defaultLayout`. Adding or removing a pane's bar changes the format, so older codes may fall back too.

In your app, `onUrl` would be `history.replaceState`, as below; this little browser keeps its own address bar instead, so the frames on this page leave yours alone. Drag an edge and watch `?layout=` change. Pass the saved code back as `layout` and the panes come back where you left them.

<DemoApp name="plants" region="url" options={{ bar: false, initial: { layout: "69", plant: "pothos", card: true } }} />

`ref.current.layout` reads the current code at any time. `setLayout(code)` applies a code without firing `onLayoutChange`; `fit(fractions)` sorts and clamps the fractions, moves to the nearest snaps and fires it. The code stores geometry only. Which panes exist is app state, such as the route, so store it separately.

## Bottom bars

Give a pane a `bar` and it gets a strip along its bottom with a title and a chevron. Clicking the strip expands the bar over the lower part of the pane; the content underneath doesn't move or resize. `height` is how tall it expands, as a `Length`: a CSS length string or a number of pixels, half the pane when left out. The bar's `content` is any React node. `toggleBar(id)` opens or closes it from code, and the layout code records which bars are open.

Here the Chart pane has a **Window** bar. Pick the way your window faces, and the plants it can't give enough sun turn hollow.

## Compact mode

Below `compactBelow` (a `Length`, `"40rem"` by default) a frame switches to compact mode. The first edge becomes a tab strip and every other edge a 12px grip whatever its `width`. Bars work as they do on a wide frame. The tab strip lists up to six panes; past six, the oldest fold into the spine, so every pane stays a tap away. The frame gets `data-compact`, so your CSS can follow.

A compact frame usually has room for one pane, so `defaultLayout` may open the wrong one. `compactLayout` is used in its place when the frame starts out compact: `[1, 1]` opens the first of three panes. It is only a default. A valid `layout` wins over it, and resizing a frame never applies it.

The width is the frame's, not the window's, so a narrow sidebar frame goes compact on a wide screen too. This frame passes `compactBelow="100vw"`, so it is always compact.

## Styling

The stylesheet sits in `@layer sashay`, so any unlayered rule of yours beats it. Theme the frame with `--sashay-*` custom properties for colour, radius, font size and shadow; every one has a fallback. `<Sashay>` passes `className` and other `div` props to the frame, and each `<Pane>` renders a `[data-sashay-pane]` element, so style them however you like. Keep the frame's `overflow: clip`: with `hidden`, a hash link can scroll the whole frame.

State shows up as attributes: `data-covered`, `data-closed` and `data-offscreen` on panes, `data-dragging` and `data-compact` on the frame. The [styling hooks](../reference/#styling-hooks) table lists them all.

This one opens at equal thirds. The chart is covered, so it holds the picked plant in view too.

## Navigation stacks

A stack is just an array in state. Picking an item adds a pane on the right; going back removes it. There are no push or pop helpers: render a `<Pane>` per entry and sashay diffs them by `id`. A new pane slides in and opens to its `focus`; a removed pane closes, gives its width to its neighbour, then leaves.

When the open panes no longer fit, the oldest fold into a spine at the left, with a tab for each. Click a tab to bring its pane back; the panes that no longer fit to its right get a spine of their own. Closed panes never fold, so a fixed workspace that fits never shows a spine.

This house opens room by room, down to the contents of a drawer.

## Server rendering

`<Sashay>` and `<Pane>` render on the server, in React Server Components too. The HTML has the whole frame, edges, bars and spine included, so nothing moves when it hydrates. On a phone it is already in compact mode: the server doesn't know the frame's width, so the CSS it sends covers each case.

```tsx
// app/page.tsx, a server component
import { Pane, Sashay } from "@vcarl/sashay/react";
import "@vcarl/sashay/style.css";

export default async function Page({ searchParams }) {
  return (
    <Sashay layout={(await searchParams).layout} style={{ height: "100vh" }}>
      <Pane id="list" title="List" focus={1 / 3}><PlantList /></Pane>
      <Pane id="plant" title="Plant" focus={2 / 3}><PlantCard /></Pane>
    </Sashay>
  );
}
```

A server component can't pass functions, so `onLayoutChange`, `onClose`, `ref` and a function as a pane's children need a client component. Put a `<Suspense>` inside a pane rather than around it. With a Content Security Policy, pass `nonce`. `data-compact` is set on hydration, so CSS that follows compact mode from the first paint should use a container query. The [Reference](../reference/#server-rendering) has the details.

## Without React

The components are a thin wrapper over `createSashay`, a vanilla DOM controller with no dependencies. Use it directly from another framework or library, or to build your own wrapper. Put one `[data-sashay-pane]` element per pane in the frame, describe the panes, and call the handle's methods; when the list of panes changes, call `update({ panes })`.
