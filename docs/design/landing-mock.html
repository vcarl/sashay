@vcarl/sashay — sliding panes for the web

Panes that sashay.

A webOS-style layout. Drag an edge and it snaps to a fraction. Throw it and it flings. Panes slide over each other instead of squishing, and the whole arrangement fits in a URL.

Why panes?

  1. Fractions, not pixels. Dividers rest at ½, ⅓, ¼ … so layouts survive a window resize.
  2. Nothing ever squishes. A squeezed pane keeps its width; the next one slides over it.
  3. Stacks go deep. Drill a thousand levels; old panes fold into a spine.
  4. Zero dependencies. Vanilla DOM controller, React wrapper optional.

Hang it in a frame.

// npm i @vcarl/sashay
import { createSashay }
  from "@vcarl/sashay";

createSashay(frame, {
  panes: [
    { id: "list",
      title: "List",
      focus: 1/3 },
    { id: "detail",
      title: "Detail",
      focus: 1/2 },
  ],
  onChange: saveToUrl,
});

01 / Snap

Snaps to simple fractions.

Dividers rest on fractions with a denominator up to six, so a layout saved on a laptop still makes sense on a monitor. The grid gets finer as the frame gets wider.

02 / Fling

Throw it.

A quick throw carries the divider one or two snaps past where you let go. Release speed is read from the last 90 ms, so a slow drag still lands exactly where you put it.

03 / Drawers

Drawers in the frame.

Any edge can open a drawer: filters, settings, a table of contents. On a phone it becomes a sheet.

Reference / createSashay

createSashay(frame, options)

Attaches to frame, finds one [data-sashay-pane] per pane, and creates every control itself: edges, the leaf × button, grips and the spine. Returns a handle.

OptionTypeWhat it does
panesPaneOptions[]Left to right. May change at any time; diffed by id.
layoutstringA saved code. Bad input falls back to defaultLayout.
onChange(code) ⇒ voidFires on release, click or keypress. Never during a drag.
