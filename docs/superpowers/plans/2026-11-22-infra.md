# Project Infrastructure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CI, a changesets/OIDC release workflow, OSS hygiene files, and the local `scripts/bugbot` OpenCode maintainer session.

**Architecture:** Two workflows (`ci.yml`, `release.yml`) that only call the root pnpm scripts. Hygiene files are short Markdown/YAML in `.github/` and the root. `scripts/bugbot` is one bash file that makes a worktree and execs `opencode`; all behaviour (provider, permissions, workflows) lives in `.opencode/`.

**Tech Stack:** GitHub Actions, pnpm, Node 24, Playwright chromium, Changesets, npm trusted publishing, actionlint, OpenCode, oMLX, `gh`.

**Spec:** `AGENTS.md` (sections "CI/CD", "Bug bot", "Rules for agents"). Scaffold plan provides root scripts; this plan does not create them.

## Global Constraints

- Root scripts available: `typecheck`, `lint`, `test`, `test:browser`, `bench`, `build`, `size`; the site plan adds `site:build`.
- Node 24; pnpm cache; Playwright chromium only.
- Actions pinned by full commit SHA (with `# vX.Y.Z` comment); `permissions:` minimal, set per job.
- No remote exists: never push, create remotes, publish, tag, or bump versions. No `NPM_TOKEN`.
- No site deploy step anywhere (deploy to a vcarl.com subdirectory is undecided).
- oMLX owns the model process (`http://localhost:8000/v1`, key `OMLX_API_KEY`, never committed); model id read from `/v1/models` (target Qwen3.8 Flash).
- Contributor code is untrusted: never executed locally by the bot.
- Bot never merges, approves its own work, publishes, tags, or bumps versions.
- Docs stay short.

## Review Focus

- PR from a fork: CI must not receive secrets; workflows use `pull_request` (never `pull_request_target`). Test: actionlint plus grep for `pull_request_target`.
- Release job run on a push with no pending changesets: must open no publish and not fail. Test: `pnpm changeset status` locally on empty state.
- `bugbot` with no remote / `gh` unauthenticated / oMLX down / `OMLX_API_KEY` unset: must print a clear message, not hang or start a server.
- `bugbot` run twice in the same second: worktree path/branch must not collide.
- Compound shell commands hiding a denied command (`cd x && gh pr merge 1`): must be blocked (OpenCode checks every subcommand; verify).

### Task 5: OpenCode config and agent prompt

**Files:**
- Create: `.opencode/opencode.jsonc`, `.opencode/agents/bugbot.md`

**Interfaces:**
- Consumes: env `OMLX_API_KEY`; oMLX model id (substituted by the script at launch, Task 6).
- Produces: provider id `omlx`; primary agent id `bugbot`; model reference `omlx/<id>` that `scripts/bugbot` passes by overriding config (see Task 6).

Schema note: OpenCode 2.x uses the new schema (`providers`, `permissions` ordered rules with `action`/`resource`/`effect`, last match wins, `shell` action, agents as `.opencode/agents/<name>.md`, `default_agent`). The old `provider`/`permission.bash` map is wrong; confirm with `opencode debug --help` and by Step 4 below.

- [ ] **Step 1: `opencode.jsonc`**: `$schema: https://opencode.ai/config.json`; `providers.omlx` = `{ name: "oMLX", env: ["OMLX_API_KEY"], package: "@opencode/ai/providers/openai-compatible", settings: { baseURL: "http://localhost:8000/v1" }, models: {} }` (models are filled at launch, since the id comes from `/v1/models`); `default_agent: "bugbot"`; `instructions: ["AGENTS.md", "CONTRIBUTING.md"]`.
- [ ] **Step 2: Permissions** (in the `bugbot.md` frontmatter, ordered because last match wins): `shell` allow `*`; then deny, one rule each: `gh pr merge *`, `gh pr review *--approve*`, `gh api *merge*`, `gh release *`, `npm publish *`, `pnpm publish *`, `pnpm changeset publish *`, `pnpm changeset version *`, `pnpm version *`, `npm version *`, `git push --force *`, `git push -f *`, `git push *--force-with-lease*`, `git push *main*`, `git tag *`, `git reset --hard *`; `edit` deny `.github/workflows/*`, `.changeset/config.json`; version edits in `package.json` cannot be denied by pattern, so the prompt forbids them and Carl's release-PR review catches them (known ceiling). Untrusted code: deny `shell` for `pnpm install *`, `pnpm test*`, `pnpm build*`, `node *`, `npx *` ONLY IN the review-PR flow; since permissions are per-agent not per-workflow, split into two agents: `bugbot` (triage + ship fixes; own code only, may run `pnpm test`) and `bugbot-review` (subagent, mode `subagent`, shell limited to `gh *`, `git diff *`, `git log *`, `git show *`, `git fetch *`, `git checkout --detach *` denied; read/grep/glob only). Put the second in `.opencode/agents/bugbot-review.md`. Default for `bugbot-review`: `shell` deny `*` then allow the read-only commands above.
- [ ] **Step 3: `bugbot.md` body** (short, imperative; it is the system prompt). Sections: **Hard limits** (never merge, approve, publish, tag, bump versions; never execute contributor code, which includes checking out a fork branch and running install/test/build; the permission config enforces most of this, you enforce the rest); **Triage** (read issue via `gh issue view`; try to reproduce on `main` with a new failing test or a script over the repo's own code; label with `gh issue edit --add-label` using only existing labels (`gh label list` first); if details missing, comment asking for repro link/version/browser; search `gh issue list --search` for dupes and comment `Duplicate of #N`); **Ship fixes** (`git switch -c fix/<issue>-<slug>` from `main`; write failing test, see it fail, fix, see it pass, `pnpm typecheck && pnpm lint && pnpm test`; `pnpm changeset` non-interactively by writing `.changeset/<slug>.md` with `"@vcarl/sashay": patch`; `git push -u origin HEAD` normal push only; `gh pr create`; never self-approve or merge); **Review external PRs** (delegate to subagent `bugbot-review`, which reads `gh pr diff <n>` only and comments with `gh pr comment`/`gh pr review --comment` against the AGENTS.md rules: minimal code, zero deps, API matches docs/api.md, changeset present, tests present, a11y rules, perf (no re-render during drag)). End with "ask Carl when scope or API direction is unclear".
- [ ] **Step 4: Verify config loads and denies work.** `opencode debug --help` to find the config-dump subcommand; run it in the repo with `OMLX_API_KEY=x` and confirm provider `omlx`, agents `bugbot` and `bugbot-review` appear. Then non-destructively test each deny: start `opencode run --agent bugbot "run: gh pr merge 1"` (and `"run: cd /tmp && git tag v0"`, `"run: pnpm changeset version"`) against a scratch worktree; expected: each is refused by permission rules before execution. If the CLI offers a permission-check/debug command, prefer it. If no remote/oMLX is available, record the check as not run and list which denies were verified by config dump only.
- [ ] **Step 5: Commit** `.opencode/` files by explicit path.
