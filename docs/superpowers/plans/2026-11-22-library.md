# @vcarl/sashay library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `packages/sashay`: the ported layout engine, its window/spine/layout-code extension, the vanilla `createSashay` controller, plain CSS, and the `@vcarl/sashay/react` wrapper, with unit, browser and perf tests wired to the root scripts.

**Architecture:** Pure engine (`engine.ts`, ported verbatim from `raw/panes.ts`) works on one *window* of panes. `window.ts` adds the window over a deep list: offset into the list, spine folding, id diffing and the variable-length layout code. `controller.ts` owns the DOM: it measures `Length`s, paints window panes with transforms, handles pointer/keyboard, and reports codes. `react.tsx` registers `<Pane>`s via context and drives one controller.

**Tech Stack:** pnpm workspaces, TypeScript strict `nodenext`, tsdown, Biome, Vitest (node + browser mode with Playwright Chromium), size-limit, Changesets.

**Spec:** `docs/api.md` (approved; implement exactly). Background: `AGENTS.md`, `HANDOFF.md`, `raw/*` (reference only; `raw/prototype` is stale).

### DOM contract (Tasks 5, 6, 7, 8 all rely on these names)

| Element | Owner | Attributes |
|---|---|---|
| frame | app | sashay sets `data-sashay-frame`, `data-sashay-ready` (after mount), `data-dragging`, `data-compact` |
| `[data-sashay-pane=id]` | app | sashay sets `data-covered` / `data-closed` / `data-offscreen`, `inert`, inline `transform`, `width`, `z-index`, `clip-path` |
| `[data-sashay-drawer=id]` | app | sashay sets `data-open` (shown), `data-sheet` (compact), inline `transform`, `width`, `z-index` |
| `div[data-sashay-edge=id]` | sashay | `role`, `tabindex=0`, `aria-*`, `data-drawer` (pane has one), `data-open` (drawer open); children `span[data-sashay-dots]`, and for drawers `button[data-sashay-toggle]` + `span[data-sashay-title]` |
| `button[data-spine]` | sashay | text = hidden count; hidden (`hidden` attr) when offset is 0 |
| `button[data-sashay-close]` | sashay | leaf ×, `aria-label="Close <title>"` |
| `div[data-sashay-tabs]` | sashay | compact only; children `button[data-sashay-tab=id]` (`aria-pressed`) and `button[data-sashay-drawer-tab=id]` (`aria-expanded`) |
| `div[data-sashay-sheet-head]` | sashay | compact sheet title + `button[data-sashay-sheet-close]` |
| `div[data-sashay-mark]` | sashay | one per window divider, `data-primary` on the dragged one |
| `div[data-sashay-probe]` | sashay | hidden measuring element |

Panes and drawers are found with `frame.querySelectorAll("[data-sashay-pane]")` filtered to `el.closest("[data-sashay-frame]") === frame`; they are never re-parented (React owns them). Pane order is DOM order and must match `options.panes` order.

## Review Focus

1. **Stale layout code** (URL from a deeper stack after Back): must fall back to the default, never throw. Pinned in Task 3 (`decodeLayout` window-past-end) and Task 6 (`setLayout("997-48")` on 3 panes).
2. **Pane list changes mid-drag** (an app adds a pane while the pointer is down): the drag ends at its live position (settle, velocity 0) before the diff. Pinned in Task 7.
3. **Zero-width frame** (mounted hidden, or before layout): no `NaN` in transforms, not compact, correct after the first resize. Pinned in Task 6.
4. **Bad pane lists**: duplicate ids, an id without a `[data-sashay-pane]` element, or an invalid `Length` throw a clear error at `createSashay`/`update`. Pinned in Task 6.
5. **Removing everything / the only window pane**: no throw, empty window, a later add works. Pinned in Task 3 and Task 6.

### Task 3: Window, spine, dynamic panes and layout code

The engine lays out one *window*: the contiguous panes `[offset, offset + div.length + 1)`. Panes before it are in the spine; panes after it are offscreen. Every pane outside the window is closed.

**Files:**
- Create: `packages/sashay/src/window.ts`
- Test: `packages/sashay/src/window.test.ts`

**Interfaces:**

- Produces:

  export const windowEnd: (v: View) => number; // offset + div.length + 1

**Algorithms** (novel; bodies given). `eff(v, order)` = `v.div.map(i => snapV(nearest(snapV(i), order)))`, the effective divider fractions.

```ts
// Fold rule. Leading closed panes fold into the spine: any of them once a spine exists,
// otherwise only a run of 2+ (a lone closed first pane keeps its edge, as in a workspace).
// Trailing: keep exactly one closed pane's edge when panes exist past the window.
export function normalize({ offset, div }: View, n: number): View {
  const w = toWidths(div.map(snapV));
  let r = 0;
  while (r < w.length - 1 && !isOpen(w[r])) r++;
  if (offset > 0 ? r >= 1 : r >= 2) { offset += r; div = div.slice(r); }
  const w2 = toWidths(div.map(snapV));
  let t = 0;
  while (t < w2.length - 1 && !isOpen(w2[w2.length - 1 - t])) t++;
  if (t >= 2) div = div.slice(0, div.length - (t - 1));
  else if (t === 0 && offset + div.length + 1 < n) div = [...div, 12];
  return { offset, div };
}

// In window: no-op if open, else focus. Adjacent (offset-1 or end): extend the window by one
// closed pane, then focus it. Anywhere else: the window jumps to that pane alone.
// focus(k) = opensTo when its length equals the window's divider count and fit() leaves k open,
// otherwise focusPane(eff, k, sizes, order). Always normalize the result.
export function reveal(v, p, n, sizes, order, opensTo?) { … }

// close: p in window and open → normalize({ offset, div: closePane(eff, p - offset, sizes(offset, end), order) }, n); else v.

// insert: a closed pane at absolute index `at` (indices after it shift).
//   at < offset → offset + 1.  at > end → v.
//   at === end → div + [12].  else k = at - offset: div.splice(k, 0, k ? div[k - 1] : 0).

// remove: p < offset → offset - 1.  p >= end → v.
//   window of one pane → n ? normalize({ offset: min(p, n - 1), div: [] }, n) : { offset: 0, div: [] }.
//   else k = p - offset; d = open ? closePane(eff, k, …) : eff snapped to indices;
//   d.splice(max(0, k - 1), 1); return normalize({ offset, div: d }, n).
//   (Dropping boundary k-1 merges the zero-width pane k into its left neighbour, or pane 0 into pane 1.)

// diff: survivors (ids in both) must be in the same relative order, else null.
//   Removals first, highest index first, via remove() against the shrinking list.
//   Then additions in ascending index of `next`: insert(at) then reveal(at, …, next[at].opensTo).
//   If no pane of the old window survives, return null.
```

`defaultView(n, defaultLayout)`: if `defaultLayout?.length === n - 1`, `{ offset: 0, div: defaultLayout.map(x => nearest(x, 6)) }`; otherwise an equal split of the last `m = min(n, 6)` panes, `{ offset: n - m, div: [1..m-1].map(k => nearest(k / m, 6)) }`. Then `normalize`. `n === 0` → `{ offset: 0, div: [] }`.

**Layout code grammar** (URL-safe, canonical; the encoder emits exactly one string per state):

```
code      = [ offset "-" ] dividers [ "." drawers ]
offset    = %x31-39 *DIGIT          ; decimal, ≥ 1; omitted when the window starts at 0
dividers  = *HEXDIG-LOWER           ; one per window divider: its SNAPS index 0–c, non-decreasing
drawers   = 1*HEXDIG-LOWER          ; present iff D > 0, exactly ceil(D / 4) digits
```

`D` = number of window panes with a drawer. Drawer digit `j` holds drawer panes `4j..4j+3`, bit `i` = drawer pane `4j+i` open. Encoding reuses engine `encode`: `(offset ? offset + "-" : "") + encode(div, []) + (D ? "." + encode([], chunksOf4(drawers)) : "")`. Decoding: match `/^(?:([1-9]\d*)-)?([0-9a-c]*)(?:\.([0-9a-f]+))?$/`; window must satisfy `offset + V + 1 <= n` (V = dividers length); then engine `decode(dividers + drawers, V, chunk bit counts)` validates monotonic indices and bit ranges (V + chunks = 0 needs no engine call). Drawer part present when D = 0, or missing when D > 0 → null.

Design:
- `<Sashay>` renders `<div {...rest} data-sashay-frame="" data-sashay-ssr={useId()}>{children}{!mounted && <SsrStyle />}</div>` inside a context holding a registry `Map<id, PaneProps>`.

- `<Sashay>`'s layout effect creates the controller once with `onChange` and `onClose` wrappers that read the latest props through refs (`onClose(id)` calls that pane's `onClose`), and `destroy()`s on unmount. It also calls `setMounted(true)` to drop the SSR style.
- `layout` prop: applied via `setLayout` only when it changed since the previous render *and* differs from the last code reported or applied. (In the render where panes change, the prop is still the old code; it must not undo the diff.) When panes and `layout` change in the same render, `update` runs first.
- `compactBelow` changes → `update({ compactBelow })`. `keepInView` changes → `handle.keepInView(id, x)` in the Pane's layout effect.
- `ref`: `useImperativeHandle` returns a stable object forwarding to the live handle.
- Render-prop children: the Pane holds `offscreen` state, updated by a `MutationObserver` on its own element (`attributeFilter: ["data-offscreen"]`), created only when `children` is a function.
- `SsrStyle` renders `<style>` with, per registered pane in render order, a rule scoped `[data-sashay-ssr="<id>"]:not([data-sashay-ready]) [data-sashay-pane="<pane>"]`: window panes get `position:absolute; inset-block:0; left: calc(<content> * <d_k> + <spine> + <edges 0..k>); width: max(calc(<content> * <w_k>), calc(<content> * <focus>))` where `<content>` = `(100% - <spine> - (<sum of window edge widths>))`, `<spine>` = `var(--sashay-spine-width, 1.5rem)` when offset > 0 else `0px`, numbers as `<n>px`, open drawer edges use the drawer width. Panes outside the window get `visibility:hidden`. The view comes from `decodeLayout(layout)` else `defaultView`. Grid-order rounding and compact mode need pixels and are left to hydration.

## Questions for lead

1. **Covered panes are inert (api.md).** At slide-over a squeezed pane is still mostly visible (raw only made *fully* covered panes inert). Under the spec, the app's hovered-point `keepInView` use can't work, because a covered chart takes no pointer input. The plan implements the spec. Should it be "inert only when fully covered"?
2. **Spine in fixed workspaces.** Fold rule: a leading run of 2+ closed panes folds into the spine. So a workspace whose user closed its first two panes shows a spine of "2". Avoiding that would need the controller to tell stacks from workspaces (an option the API doesn't have). OK as is?
3. **`onClose` scope.** The spec says "by × or by dragging below minWidth". The plan also fires it for edge click/Enter closes (still user closes). OK?
4. **First edge.** The leftmost window edge has no divider, so it is `role="button"` (toggle only), not `role="separator"`.
5. **`<Sashay>` props.** api.md lists no `className`/`style`; the plan passes the remaining `div` props through to the frame. Separately, the spine and compact tab strip widths are `--sashay-spine-width`/`--sashay-tabs-width` CSS properties, beyond the hooks table's colour/radius/font/shadow list.
