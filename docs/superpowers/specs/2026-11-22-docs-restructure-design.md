# Docs restructure and demo apps

Approved by Carl in conversation, 2026-11-22.

## Why

The 10 docs pages carry too little content each, and their toy demos ("p1 / Open / Back" in an
empty box) look unfinished next to the landing page. Fewer, fuller pages; demos that look like
small real products.

## Pages

| Page | Contents |
|---|---|
| Landing | Unchanged, except: the feature cells link into Guide sections, and a "See it work" band below the feature grid embeds both demo apps. |
| **Guide** | One long page, anchored sections: install → first frame → layout in the URL → drawers → compact mode → styling. Each section grows the finance app by one feature (its running example), so the reader builds one real app. |
| **Demos** | Both apps full size, each with a collapsible source panel. |
| **Reference** | The current API, React and Accessibility pages merged, with an on-page table of contents. Styling hooks live here. |

The old page URLs redirect to the matching anchors.

## Demo 1: finance app (fixed workspace)

Shows drawers, `keepInView`, layout in the URL, compact mode.

1. **Overview**: portfolio value chart. The edge drawer "Interval" picks 1W / 1M / 1Y / 5Y.
2. **Period**: clicking a bar opens that period's transactions. Squeezing Overview keeps the
   selected bar in view (`keepInView`).
3. **Details**: clicking a transaction opens its details. Leaf × closes it.

## Demo 2: house explorer (navigation stack)

Shows dynamic panes and the spine. A pun-adjacent tree: a house's rooms, furniture, drawers
and their contents.

- Directories are places that hold things (House → Kitchen → Dresser → Top drawer → Tin box…),
  up to **6 levels deep**, with **0–6 entries** per directory. Empty drawers are allowed and
  say so.
- Opening a directory pushes a pane; going back pops it. Opening an item (a file) shows a
  preview pane at the end: the item's name, a one-line description and a small flat SVG
  illustration or colour swatch. No emoji.
- Narrow frames fold the oldest levels into the spine.

## Shared calls (the lead's)

- Data is seeded and deterministic (the same on every load), generated by a tiny in-repo
  generator with a fixed vocabulary. No dependencies.
- Charts are hand-rolled SVG. No chart library.
- Visual language: the site palette. Cobalt, butter and mint panes; ink rules; tomato for
  selection; site type. They should look like small real products, not grey wireframes.
- The demos are vanilla `createSashay` modules, reused across Landing, Guide and Demos. The
  React page keeps its own small React example.

## Edge affordance (library default CSS)

Edges (the "rails"/stiles) scan as decoration. Make them read as controls in sashay's default
CSS, so every consumer benefits, and the site's stiles inherit it:

- a visible grab icon (a vertical grip of dots or bars) centred on each draggable edge;
- a left and right border on the edge;
- a hover/active state.

Compact-mode grips keep a smaller version. Contrast follows WCAG non-text contrast (3:1).
